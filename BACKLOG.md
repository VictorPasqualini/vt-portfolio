## High priority

### Deploy pipeline

Hosting decided: **Vercel** (Netlify was tried first and dropped). Import the repo and take the defaults — Vercel detects Next.js and serves the export, so no config file is committed. Remaining: set `NEXT_PUBLIC_SITE_URL` in the project's environment variables, and set up a custom domain if Victor wants one. Preview deploys per branch/PR are on by default.

Worth reconsidering now that the host runs Node: dropping `output: 'export'` would let the server handle the two things the static build can't. `/` could redirect for real instead of via a client-side stub, and `app/[locale]/layout.tsx` could become the root layout so `/pt` ships `lang="pt"` in its HTML. The cost is that the build stops being host-agnostic.

### Blog / Articles section

Requested 2026-09-22, replacing the "won't do" entry below. The idea: publish Victor's own technical articles on the site instead of only linking out, the way ricardohsmello.com runs `02 / Articles — Technical writing`.

Worth doing, with a caveat: the build is the cheap part and the cadence is the expensive one. The site is a static export, so local posts need no server — MDX files under `content/posts/`, a `generateStaticParams` route at `app/[locale]/blog/[slug]/`, and the existing `app/sitemap.ts` picks them up. That is roughly a day of work. Writing two posts a month for a year is not.

Two real costs before starting:

- **Bilingual.** Every other string on this site exists in both locales. A post does not translate itself, so either each post ships `en` + `pt` or the route needs a per-post fallback ("this post is only available in English") — decide which before the first post, because retrofitting the fallback means touching every published URL.
- **Empty-section risk.** A `02 / Articles` header over two posts from eight months ago reads worse than no section at all. The block should stay unmounted until there are at least three posts.

Suggested order, so nothing is built speculatively:

1. **Write two or three posts first**, anywhere — Medium, dev.to, LinkedIn. No code.
2. **Ship an Articles section that links out**, reusing the existing card and tag styling. Cheap, and it proves the cadence is real.
3. **Only then move to local MDX**, so the SEO and the `Person` JSON-LD land on his own domain instead of a platform's. At that point the linked-out cards become the same component pointing at internal routes.

Open questions if it gets picked up: syntax highlighting (Shiki at build time, since there is no server), RSS feed, and whether posts get their own OG cards — `scripts/render-og.mjs` already renders per-page cards and could take a title argument.
